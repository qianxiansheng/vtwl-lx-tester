# 产测上位机UI结构化需求文档（供AI生成程序使用）
> 技术背景：Windows上位机，支持 USB（WinUSB，优先）与 UART 两种端口，最多6个工位（常规4工位）；1端口=1工位=1块测试板+1个DUT被测板；业务模型：多工位循环产测，RF无线类测试全局互斥锁，功耗可并行。
> 通信协议见 `产测协议规范.md`（上位机 - 测试板帧协议、指令码、result_code）。**协议与本文档冲突时以协议为准。**
> UI设计原则：极简工业产测界面，大按钮方便车间点击；状态颜色强提示；分模块布局；禁止复杂花哨控件。

## 整体窗口布局（主窗口可自由拖拽调整大小；内部为 Dock 停靠布局）
主窗口初始尺寸按显示器 DPI 缩放并居中，用户可拖拽调整大小。窗口内部为可停靠（Dock）面板，用户可拖动调整，布局自动保存；菜单「视图」可显示/隐藏面板、重置为默认布局。
面板划分（默认布局从上到下）：
1. 【控制台】：软件名称+版本号、全局状态，以及全局操作按钮区（大尺寸操作按钮，全局控制整套产测流程）
2. 【工位管理】：添加、管理工位实例，最多6个工位卡片
3. 【测试参数】（左下）：按测试类别分组，每组包含公共参数（重试次数）+ 专用阈值参数
4. 【日志】（右下）：滚动输出日志、错误、时间戳，支持选择复制
5. 【统计】：本次运行的测试统计（见区域5）

## 区域1：端口/工位管理区
功能：管理COM/USB端口，一个端口对应一个工位，上限6工位。
控件：
1. 按钮：**添加工位端口**（大按钮），每点击一次新增1个工位卡片；达到6个后按钮置灰不可点击。
2. 工位卡片（最多6张，横向平铺，窗口宽度足够；超出可横向滚动）
> 单张工位卡片内容（单工位）：
- 工位编号标签：工位#1 / #2 … #6
- 端口类型选择：USB（默认）/ UART
- 端口选择下拉框：
  - USB：列出当前在位、VID/PID 匹配的 USB 设备（VID/PID 在「通信参数」中配置，默认 0000），显示名为设备序列号（无序列号时为实例 ID 最后一段）；未绑定 WinUSB 驱动的设备显示但不可选；
  - UART：COMx 列表；
  - 端口按设备实例 ID 记录：测试板有唯一 USB 序列号时，换 USB 口也能识别；无序列号时与物理 USB 口绑定。
- 按钮：【连接端口】【断开端口】【移除本工位】
- 两级连接状态指示灯（色块）：
  - 测试板：灰色未连接；黄色连接中；绿色已连接；红色断开/通信异常
  - DUT：灰色未连接；黄色握手中；绿色DUT连接就绪；红色DUT无应答/通信异常

> 「连接端口」流程：打开端口 → 心跳 `REQ_TESTBOARD_ALIVE` 收到应答（测试板已连接）→ `REQ_GET_VERSION` 读取并记录固件/硬件版本 → `REQ_CONN_CHECK_DUT` 握手成功（DUT就绪）。
> 连接后持续以 500ms 间隔发送心跳；心跳/指令连续超时 3 次或端口物理断开 → 测试板断开（DUT 同时视为断开）。
> 测试板-DUT 指令超时（应答 result_code 为 `RET_ERR_DUT_NO_RESPONSE` 等）→ DUT 断开，需要重新 `REQ_CONN_CHECK_DUT`。
- 本工位本地状态（色块）：`准备中(灰) / 准备就绪(绿) / 测试进行中(黄) / 测试结束(蓝)`
- 本工位测试结果简要展示：展示最近一轮综合结果 PASS(绿)/FAIL(红)/ABORT(橙)
- 写入产测标志状态（色块）：待执行(灰) / 执行中(黄，显示当前步骤) / PASS 已写入(绿) / FAIL(红) / ABORT(橙) / 跳过(灰)
- 卡片下半部分「测试板 / DUT / 工位状态 / 本轮结果 / 无线收发包 / 频偏 / 功耗 / 产测标志」为左标签 + 右状态条，所有状态条左右边缘对齐

> 工位编辑限制：
- 测试进行中不能添加工位；
- 端口已连接（DUT 非「未连接」）时不能更换端口、不能移除工位；
- 同一端口不能被两个工位同时选择，冲突时弹窗提示。

> 全局就绪条件：**所有已添加工位全部达到DUT连接就绪（绿色）**，系统全局状态切换为「准备就绪」；只要任意工位断开，退回「准备中」。

## 区域2：全局操作按钮区（醒目大按钮，尺寸大于普通按钮，适配鼠标/触屏点击）
按钮横向排列，根据全局状态自动启用/置灰。
按钮清单：
1. **开始测试**
   - 启用条件：全局状态=准备就绪；其他状态置灰
   - 点击动作：触发整套产测流程，全局状态切换为【测试进行中】
2. **下一轮**
   - 启用条件：全局状态=测试结束；其余状态置灰
   - 点击动作：清空本轮结果，复位所有工位业务状态，全局切回【准备中】，等待DUT状态校验，准备下一轮循环
3. **紧急停止**（红色按钮，任何时刻都可用，不置灰）
   - 动作：终止全部工位测试任务，通知所有测试板终止业务，释放资源锁；全局回到准备中状态
4. **清空日志**

### 全局主状态（软件顶层状态，界面顶部文本标签醒目展示）
4种状态：`准备中` / `准备就绪` / `测试进行中` / `测试结束`
状态流转严格遵循：
准备中 →【全部工位DUT连接成功】→ 准备就绪
准备就绪 →【点击开始测试】→ 测试进行中
测试进行中 →【所有工位全部测试项执行完毕】→ 测试结束
测试结束 →【点击下一轮】→ 准备中
任意时刻紧急停止：直接跳转至准备中

## 区域3：测试参数配置区
> 测试项固定3种：①无线收发包测试 ②频偏测试 ③功耗测试
按测试类别分为3组（分组框，一一对应3个测试类型），每组由「公共部分」+「专用部分」组成；参数修改实时生效，不需要确认弹窗。

1. 【无线收发包测试】
   - 公共部分：重试次数（数字，0~5，默认0）
   - 专用部分：
     - 最低收包率(%)，默认95：DUT 收包率 = 被测板收包数 / 总发包
     - 最低发包率(%)，默认95：DUT 发包率 = 测试板收包数 / 总发包
     - 最低 RSSI(dBm)，默认 -70
   - 判定：收包率、发包率、RSSI 均 ≥ 对应阈值 → PASS；任一小于 → FAIL
2. 【频偏测试】
   - 公共部分：重试次数（数字，0~5，默认0）
   - 专用部分：最大绝对频偏(KHz)，默认50
   - 判定：abs(实测频偏) ≤ 阈值 → PASS，超出 → FAIL（CFO 原始 int16 值换算为 KHz 的系数待协议补充）
3. 【功耗测试】
   - 公共部分：重试次数（数字，0~5，默认0）
   - 专用部分：最大功耗(uA)，默认100
   - 判定：平均电流 ≤ 阈值 → PASS，超出 → FAIL（最大/最小电流仅记录）
4. 【产测标志】（所有工位共用，可配置）
   - 指令重试次数，默认 3（`REQ_RESET_DUT`、`REQ_SET_FT_FLAG` 失败后的重试次数；握手、读回不重试）
   - 读回延时(ms)，默认 500（写入成功后延时多久发送 `REQ_GET_FT_FLAG`）
5. 【通信参数】（所有工位共用，可配置）
   - 普通指令应答超时，默认 200ms（连续 3 次超时判定测试板断开）
   - `REQ_CONN_CHECK_DUT` 应答超时，默认 600ms
   - 业务状态轮询间隔，默认 100ms
   - UART 波特率，默认 115200（下次连接生效）
   - USB VID / PID（十六进制），默认 0000 / 0000；修改后自动刷新端口列表

> 各测试类别的「公共部分」另含「业务超时(ms)」：启动指令发出到拿到结果的总时长，超时即 ABORT；默认收发包 10000、频偏 5000、功耗 10000。
> 频偏「专用部分」另含「CFO 换算系数(Hz/LSB)」，默认 1（待协议确认）；注意默认系数下 int16 最大只能表示 ±32.767 KHz。

> 重试策略（上位机控制）：FAIL 不重试；仅「非紧急停止」造成的 ABORT 按该测试类别的重试次数重试；每次重试前先 `REQ_RESET_DUT`，再 `REQ_CONN_CHECK_DUT`。

### 3‑1 用户配置持久化
- 用户配置保存到工作目录下的 `config.json`：各测试类别参数 + 通信参数 + 工位列表（工位编号、端口类型、所选端口）；
- 启动时加载；运行中每 5 秒检查一次，有修改才写盘；退出时再保存一次；
- 文件缺失时使用默认值；字段缺失用默认值，越界值自动修正；文件损坏时使用默认值并弹窗提示，原文件备份为 `config.json.bad`；
- 全局状态、DUT 连接状态、测试结果等运行时状态不持久化。

> 说明：阈值仅上位机使用；测试板只返回 `result_code` + 原始测量值，**PASS / FAIL / ABORT 全部由上位机判定**：
> - `result_code == RET_OK` 且原始值全部在阈值内 → PASS；
> - `result_code == RET_OK` 但原始值超出阈值 → FAIL；
> - `result_code != RET_OK`、业务总超时、紧急停止打断（`RET_ERR_ABORTED`）→ ABORT（无有效测量数据，不计入良率 FAIL）。

### 每个工位内部测试项状态展示（工位卡片展开/子面板）
每个工位下，3个测试项独立状态显示：
每个测试项显示：测试项名称 + 状态色块标签
状态：
- 灰色：待执行
- 黄色：等待中 / 执行测试中
- 绿色：PASS
- 红色：FAIL（指标不达标）
- 橙色：ABORT（执行异常，无有效数据）

> 业务调度逻辑（上位机实现，UI仅展示状态，不需要UI做调度逻辑）
1. 每个工位测试顺序固定：无线收发包 → 频偏 → 功耗；
2. RF类测试（收发包、频偏）全局互斥锁，同一时间只能1个工位跑RF测试；工位拿到锁后连续完成两项 RF 测试再释放；未拿到锁的工位在上位机侧排队，不向测试板下发指令；
3. RF完成后的工位，立即执行功耗测试，可多工位并行；
4. 功耗测试完成后（DUT 处于低功耗、串口静默）：
   - 3 项测试**全部 PASS** → 写入产测标志：
     1. `REQ_RESET_DUT` 复位 DUT，失败按「指令重试次数」重试，仍失败 → 本轮 FAIL；
     2. `REQ_CONN_CHECK_DUT` 握手，失败（含超时）→ 本轮 FAIL；
     3. `REQ_SET_FT_FLAG` 写入产测标志，失败按「指令重试次数」重试，仍失败 → 本轮 FAIL；
     4. 延时「读回延时」后 `REQ_GET_FT_FLAG` 读取产测标志，读回值为 1 → 本轮 PASS，否则（含超时、result_code 非 0）→ 本轮 FAIL；
     - 写标志过程中被紧急停止或测试板断开 → 产测标志 ABORT，本轮 ABORT；
   - 未全部 PASS → 不写产测标志（显示「跳过」），只下发 `REQ_RESET_DUT` 再 `REQ_CONN_CHECK_DUT`；
   - 握手成功才算该工位进入空闲 / 测试结束；
5. 单项业务执行方式：下发启动指令（测试板立即 ACK）→ 按轮询间隔发送 `REQ_GET_TEST_STATUS`，直到状态为「空闲」→ 发送对应 `GET_RESULT` 读取结果；状态为「异常」或超过业务总超时 → ABORT；
6. 测试进行中某工位 DUT/测试板断开：该工位剩余测试项标记 ABORT，其他工位继续，全部结束后进入「测试结束」。

## 区域4：日志输出区
只读，滚动追加（已在底部时自动跟随）；每一条日志带时间戳；警告橙色、错误红色。
支持复制：单击 / 拖拽 / Shift+单击按行选择，Ctrl+C 复制选中，Ctrl+A 全选；工具栏与右键菜单提供「复制选中 / 复制全部 / 清空」。
输出内容示例：
`[2026‑09‑30 16:xx:xx] 工位#2 DUT连接就绪`
`[2026‑09‑30 16:xx:xx] 全局状态切换为：准备就绪`
`[2026‑09‑30 16:xx:xx] 工位#1 开始执行无线收发包测试`
`[2026‑09‑30 16:xx:xx] 工位#1 无线收发包测试：PASS，收包率97.2%，发包率98.5%`
`[2026‑09‑30 16:xx:xx] 工位#3 频偏测试：ABORT，result_code=0x10（DUT无应答）`

## 区域5：统计窗口与结果文件
- 统计窗口：按工位和合计显示本次运行的测试数、PASS、FAIL、ABORT 数量和良率（良率 = PASS / (PASS + FAIL)，ABORT 不计入）；
- 结果文件（CSV）：每个工位每轮测试完成后追加一行，字段包含：时间、工位、端口、dut_id（保留，暂无查询指令，留空）、各测试项原始值（总发包、测试板收包数、被测板收包数、RSSI、CFO 原始值、平均/最大/最小电流）、各测试项 result_code、各测试项判定结果、产测标志（读回值、result_code、判定、说明）、综合结果。
- 程序升级导致 CSV 字段变化时，若当天文件表头不同，自动改写到 `results_YYYYMMDD_2.csv`（依次递增），避免列错位。

# 边界约束（给AI编码时必须遵守）
1. 工位上限6，添加按钮到6个自动disable；
2. **全局就绪必须全部已添加工位DUT都连接成功**，非测试进行中时只要一个工位断开，退回准备中（测试进行中的断开见区域3调度逻辑第6条）；
3. 流程流转不能跳过状态：不允许直接从准备中跳到测试进行中；
4. 紧急停止永远可用；
5. 阈值配置仅保存在上位机；下发给测试板的是测试指令，阈值不下发给测试板；
6. ABORT含义：没有有效测试结果，由上位机根据 result_code / 业务超时 / 紧急停止判定，上位机不拿阈值做判断；PASS/FAIL由上位机拿测试板上报原始值与配置阈值对比得出；
7. 上位机保存每一轮所有工位、所有测试项结果到 CSV（见区域5）；UI不需要复杂报表；
8. 测试板只返回 result_code 和原始测量值，**不做指标合格判断，不输出 PASS/FAIL/ABORT**；
9. 紧急停止：对所有已连接工位并行下发 `REQ_STOP_CURR_TASK`，释放 RF 锁，被打断的测试项标记 ABORT 且不重试。

# 不需要实现的功能（明确告知AI，不要额外增加）
1. 不要做用户登录；
2. 不要做图表曲线；只展示数值、状态色块；
3. 不需要保存工程文件；仅用户配置持久化到 config.json（见 3‑1）；
4. 不需要复杂的自定义测试脚本，固定3项测试。

# 开发辅助
- 提供「模拟测试板」传输层（调试菜单可切换），不接硬件即可模拟正常结果、FAIL、各类 result_code、超时，用于验证调度、RF 锁、重试、紧急停止。
